Current environment is MINGW64_NT-10.0-22631 (MSYS2/Git Bash on Windows). The /dev/null character device is broken/corrupted — shows 'No such device or address' error. Causes all terminal/file tools to fail with 'FileNotFoundError: [Errno 2] No such file or directory: nul' because Hermes Agent internally redirects to /dev/null. This is a platform-level issue that needs to be fixed by re-creating /dev/null as character device (major 1, minor 3) with permissions 666.

On this MSYS2/MINGW64 system, ALL terminal commands go through bash which crashes on startup if /dev/null is broken. The Hermes tool system internally invokes bash for every command, so fixing via terminal is impossible from within. Need external fix: someone must run 'mknod -m 666 /dev/null c 1 3' or 'python3 -c "import os; os.unlink(\"/dev/null\"); os.mknod(\"/dev/null\", 0o20666, device=os.makedev(1,3))"' from a DIFFERENT shell (Windows CMD, PowerShell, or a separate Git Bash window).
